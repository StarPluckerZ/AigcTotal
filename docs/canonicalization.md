# Canonicalization（报告 canonical JSON 规范，v1 冻结）

存证报告的 canonical 字节形态。**v1 永不修改；字段只增不改；验证器必须忽略未知字段。**

## 1. 基座：RFC 8785（JCS）

- 对象键按 UTF-16 码元排序；
- 无空白；
- 数字按 ECMAScript Number::toString 规则；
- 字符串最短转义（JSON 必需转义 + 最小化）。

实现须通过 RFC 8785 附录测试向量（CI 校验）。

## 2. 类型约束（schema 层）

- 信封内**只允许整数**，取值域 ±(2⁵³−1) 安全整数；**禁止浮点**；
- 验签前先做 schema 校验，浮点出现即拒绝（不进入 canonical 化）。

## 3. 固定格式

| 字段类别 | 格式 |
|---|---|
| 时间 | RFC 3339 UTC，秒精度，Z 后缀：`2026-09-21T08:30:00Z` |
| 哈希 | `sha256:` + 64 位小写 hex |
| 报告 ID | ULID（Crockford base32，26 字符） |
| kid | `k` + 公钥 DER 的 SHA-256 全长 64 位小写 hex |

## 4. 数据不规范化

透传的文件数据（含中文平台名、提示语等）**不做 NFC 归一化、不改大小写**——逐字 echo；字符集合法性由附录 E 校验负责，规范化即引入判定分歧。

## 5. 版本政策

- canonical 形态与 `version: 1` 绑定，永不修改；
- 新字段只能以"旧验证器可忽略"的方式追加；
- `version` 只在推倒重来的场景（永不期望）才递增。
